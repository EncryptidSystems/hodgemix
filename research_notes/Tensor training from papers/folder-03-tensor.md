# Folder 03 as a tensor-only training arrangement

Purely tensor, as used here, means the only inputs are safetensors weight arrays (one base and zero or more contributors) plus scalar mix weights, and the output is a weight array. A calibration sentence, a tokenizer string, a label, a loss, or a backward pass puts a step outside that class. The arrangement below uses only steps that `paper_v2` Algorithm 1, the 18 October architecture tex, or the existing `train/` and merge code already define. A line in a paper or a comment in Go is a specification until a Proof environment, a tagged [D] argument, or an explicit “proved” sentence says otherwise. No step below is a new optimizer.

## Steps of Algorithm 1 and the architecture pipeline

### Takeaway

The tensor-only chain already written is: spline the matrices onto the index grid, phase-correlate, copy only gap-certified fibres, split by a mixed-radix DFT, run ternary TIES on the curl, lock or leave the harmonic band, restore the base residual, absmean-ternarize, and pack BNZ4. The architecture pipeline inserts, around that chain, a calibration forward, a union vocabulary, pin-mean, an OV-chart rewrite, a surgery cap, and a repair loop. Those four of the six inserted stages read sentences or tokenizer strings. The OV chart and the neck-limb cut read weight arrays. Nothing in the chain is a proved improvement of a model.

## The DTFT lock

### Takeaway

Algorithm D reads the phases and the peak frequencies of the near-harmonic DFT sequences of the weight grids. The \(\omega_i=0\) lock reads the same kind of phases and then sets every natural frequency to zero. `paper_v2` and `dtft_lock` both say that choice locks the population, so the order parameter does not select a contributor. Algorithm D is the specified replacement. The code’s default path records those frequencies and then accepts a mode only when four gates hold; a rejected mode stays on the base sequence. That gate is a specification in the current `synthD`. It is not a proof that the accepted modes improve a model.

## Monodromy

### Takeaway

Trivial holonomy is a test on the frames the seed assigns to tensor ends. Those frames are permutations and cyclic shifts of the weight grids, so the product in Definition 1 can be computed from the tensors and the scalar weights do not enter it. The architecture tex says the code does not compute it. A nontrivial value means, by the proved Proposition 1, that there is no single frame in which the merge is a pointwise average. The sentence that tells a trainer what to do instead is explicitly open: average where the defect is zero, and keep separate experts where it is positive. That sentence does not say to write the base array on the loop. Conjecture 1, including the claim that a local trivial-holonomy solution exists when every tensor cost is irreducible, is labeled a conjecture.

### Cited Findings

- Definition 1. For a cycle of tensors, \(\mathrm{Hol}(c)\) is the product of the inverse frame at each tensor’s incoming end times the frame at the previous tensor’s outgoing end, in the symmetric group of the axis. The frames are the seed’s per-tensor permutations, \(S_n\) from the Re-Basin assignment, or \(U(1)\) phases from the cyclic shift of paper v2 Eqs. (12)–(13). The DTFT lock’s per-mode phases and the OV chart’s linear map are additional transports in the same definition. The five listed loops are the OV head loop, the FFN loop, the QK loop, the depth product of residual frames, and the DFT torus loop whose winding is the wrap of those phases. The defect is \(\eta(h)=1-\mathrm{fix}(h)/n\), and \(\eta=0\) if and only if \(h=I\). The transport error is the Frobenius norm \(\|P_h W-W\|_F/\|W\|_F\) on the base tensor. The abstract says the holonomy “is computable from quantities the merge already produces.” — [monodromy_moe.pdf](file:///C:/Users/grego/Downloads/Research/03%20Hodge-Kuramoto%20Model%20Merging/monodromy_moe.pdf)
- Proposition 1, proved in the text by a spanning-tree gauge. There is a gauge, one frame per axis vertex, in which every tensor’s alignment is the identity relative to the base, so the merge is a pointwise average in one global frame, if and only if \(\mathrm{Hol}(c)=I\) on every cycle. The perplexity \(1.3\cdot 10^7\) is “smoke-test observations, not tests of the proposition.” No runs are reported. — [monodromy_moe.pdf](file:///C:/Users/grego/Downloads/Research/03%20Hodge-Kuramoto%20Model%20Merging/monodromy_moe.pdf); [folder-03.md](file:///C:/Users/grego/hodgemix-go/research_notes/Research%20papers%2001%2002%2003/folder-03.md)
- Section 5. “By Proposition 1, averaging is consistent exactly where the relative holonomy of \(m\) and the base is trivial. This gives a criterion, not fixed by any existing paper and listed as open: average where \(\eta=0\); keep separate experts where \(\eta>0\).” Static routing, one contributor per layer, is consistent when the chosen residual frames agree at each boundary. Which Champ implementation is adopted is open. Prediction P7, where \(\eta>0\) a two-expert model has lower loss than the average, is in the protocol and is not run. — [monodromy_moe.pdf](file:///C:/Users/grego/Downloads/Research/03%20Hodge-Kuramoto%20Model%20Merging/monodromy_moe.pdf)
- Conjecture 1 is titled a Bolibruch-type obstruction for local frames. Proposition 3, frames for every representation by putting the data on the chords, is proved. — [monodromy_moe.pdf](file:///C:/Users/grego/Downloads/Research/03%20Hodge-Kuramoto%20Model%20Merging/monodromy_moe.pdf)
- Architecture v2, monodromy table: “Holonomy, depth monodromy \(\mathcal T\), defect \(\eta\), \(\Delta_{\mathrm{RH}}\): not computed; the seed’s per-tensor permutations are not exported in a form from which they could be.” The averaging-versus-experts criterion is not implemented. One frame per axis node exists for the cell layout, which the tex calls the single-frame gauge of Proposition 1; the merge seed still aligns per tensor. — [hodgemix_architecture_v2.tex](file:///C:/Users/grego/Downloads/Research/03%20Hodge-Kuramoto%20Model%20Merging/hodgemix_architecture_v2.tex)

### Inferences

- The test itself, Definition 1 and \(\eta\), uses the seed permutations and shifts, the DTFT phases if those are kept, and the base weight array for the Frobenius quotient. All of those are functions of the weight arrays. A calibration sentence is not an input of the formula. The code path that would multiply the permutations is absent, so a tensor-only trainer that follows the code does not branch on holonomy.
- What a nontrivial holonomy tells a trainer, on the proved statement, is that the single-frame average does not exist. The action the paper writes next, keep a separate expert, is the open criterion in section 5. Writing the base value onto that loop is a different operation, the surgery cap, and the monodromy paper does not state it. Conjecture 1 does not state it either. A trainer that must emit one weight array has, from these pages, the proved obstruction and an open proposal to emit more than one expert tensor.
